# 플레이 로그 모음

실게임 실행 기록을 최신순으로 모았습니다. 링크를 누르면 원본 로그가 열립니다. 모두 Windows, TETR.IO Desktop 10.0.0에서 측정했습니다. 낯선 용어는 [README의 용어](../README.md#용어)를 보세요.

## 읽는 법

- **전체 PPS:** 실행 전체의 피스/초입니다. 앱 연결, 시작 메뉴 대기(8초), 자동 보정, 레벨 전환 연출이 모두 들어갑니다.
- **TURBO 실효 PPS:** TURBO로 플레이한 구간만 센 피스/초입니다. 로그에 20피스마다 찍힌 값의 중앙값과 최고값을 적었습니다.
- **오배치·레벨 전환:** 화면으로 센 추정치입니다. BASIC·RAPID 구간에서는 레벨 전환 한 번을 두 번으로 세는 경우가 있습니다.
- 기록마다 보드와 피스 순서가 다릅니다. 같은 조건에서 비교한 실험이 아닙니다.

1. 콘솔 명령만으로 RAPID·SINGLE → RAPID·QUAD → BASIC·QUAD → TURBO·QUAD로 바꿔 가며 플레이했습니다. QUAD로 바꾼 뒤 지운 454줄 중 432줄(95%)이 쿼드였습니다. 재현 명령: `node probe/console_drive.js <로그> 150:2-q 500:1-q 650:3-q -- --mode rapid --pieces 1300 --restart-every 0`
2. 보정 프로필이 없던 창 크기에서 TURBO가 스스로 보정한 뒤 플레이했습니다. 전체 PPS가 낮은 것은 보정 시간(약 2분 반)이 포함됐기 때문입니다.
3. 두 런이 한 로그 파일에 들어 있습니다. RAPID 런은 TURBO로 시작했지만, 앱이 재시작되며 창 크기가 바뀌어 RAPID로 진행됐습니다.
4. 실제 레벨 전환은 180~220피스 사이의 1번입니다. 오배치 1회도 이 전환 중에 나왔습니다.

쿼드 횟수는 QUAD를 추가한 09-25부터 기록합니다. 09-25 TURBO·QUAD 1,500피스 런에서는 RAPID로 세 번 넘겼고, 세 번 모두 TURBO로 돌아왔습니다. 레벨 전환 때 2번(스택 5줄에서 복귀), 스택이 12줄에 닿았을 때 1번(6줄에서 복귀)입니다.
