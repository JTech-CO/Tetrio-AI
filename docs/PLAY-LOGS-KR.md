# 플레이 로그 모음

실게임 실행 기록을 한 표에 모았다. 최신순이며, 각 행의 링크가 원본 로그다. 모든 기록은 Windows / TETR.IO Desktop 10.0.0 / Chrome 138에서 측정했다.

## 읽는 법

- **전체 PPS**: `run.js` 종료 줄의 값이다. 앱 연결, 시작 메뉴 대기(8초), 자동 보정, 레벨 전환 연출까지 포함한 벽시계 기준이다.
- **실효 PPS**: TURBO가 보고하는 `turboStats.effectivePps`이며 TURBO로 플레이한 구간만 센다. 보정 시간은 빠진다. 로그에 20피스마다 찍힌 값의 중앙값과 최고값을 적었다.
- **오배치**: 직전 예측과 다음 화면이 달랐던 턴 수로, 화면으로 추정한 값이다.
- **스테이지업**: 필드 아래 숫자의 변화로 센 추정치다. RAPID 구간에서는 한 번의 전환을 두 번 세는 경우가 있다.
- **쿼드**: 쿼드 카운터는 QUAD 방식을 추가한 2026-09-25부터 기록된다. 그 전 기록은 `—`로 표시했다.
- 순차 실행이라 기록마다 보드와 피스 순서가 다르다. 통제된 A/B 비교가 아니다.

### 기록별 메모

- **09-25 TURBO·QUAD 1,500피스**: QUAD만으로 돌린 첫 장기 실행이다. RAPID로 세 번 넘겼고 세 번 모두 TURBO로 복귀했다.
  - 레벨 전환 때 2회: 스택 5줄에서 복귀했다.
  - 스택이 12줄에 닿았을 때 1회: 6줄에서 복귀했다.
- **09-25 전환 테스트 1,300피스**: 사람 대신 `probe/console_drive.js`가 정해진 피스 수에 콘솔 명령을 입력했다. 입력 명령은 당시 형식(`quad` → `1` → `3`)이다. QUAD로 바꾼 뒤 지운 454줄 중 432줄(95%)이 쿼드였다. 현재 명령 형식으로는 `node probe/console_drive.js <로그> 150:2-q 500:1-q 650:3-q -- --mode rapid --pieces 1300 --restart-every 0`로 재현한다.
- **09-24 TURBO·SINGLE 1,000피스**: 창 크기별 보정 프로필을 쓴 재검증이다. 레벨 전환은 없었다.
- **09-24 자동 보정**: 보정 프로필이 없는 창 크기(1295×997)에서 TURBO가 스스로 보정한 뒤 플레이했다. 전체 PPS가 낮은 것은 보정 시간이 포함됐기 때문이다.
- **09-23 로그 파일**: 두 런이 한 파일에 들어 있다.
  - TURBO 1,000피스: 440피스 지점부터 기록돼 있다.
  - RAPID 1,000피스: TURBO로 시작했지만 앱이 재시작되며 창 크기가 바뀌어 보정이 무효가 됐고, 그래서 RAPID로 돌았다. RAPID 오배치 회귀를 고친 뒤 장기 확인한 자료다.
