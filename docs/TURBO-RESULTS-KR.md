# TURBO 구현·검증 요약

2026-09-21 · Windows / Node.js 25.9.0 / TETR.IO Desktop 10.0.0 · 뷰포트 1295×999, DPR 2.

## 최종 결과

**500피스 / 93.940초 = 5.323 PPS로 합격.** 의심 피스·재동기화·입력 오류·폴백 모두 0회.
[실측 JSON](turbo-validation-500-final-2026-09-21.json). 자동 테스트는 70개 통과했다.

연결·초기 보정·준비 주행 60피스는 측정에서 제외하고, 실행 중 검증·복구·키 해제 시간은 포함했다.
합격 조건은 500피스 이상, 의심 피스를 제외한 PPS ≥5, 의심 피스 ≤3%, 강제 재동기화 ≤1%, 입력 오류·폴백 0회다.

**한계:** 최종 구간에는 레벨 전환이 없었다. 1,000피스 완주는 이후 확인됐다(아래 2026-09-23 재검증).
이전 버전의 장기 성공 이후에도 전환·캡처 지연으로 실패한 시도가 있었다. 다른 환경에서 같은 속도나 무오배치를 보장하지 않는다.
의심 피스는 불일치 검증 구간 전체의 피스 수이며, 실제 오배치 수와 같지 않다.

## 2026-09-23 재검증 (1,000피스)

**1,000피스 / 208초 완주, 실효 5.03 PPS.** 의심 피스·강제 재동기화·오배치·RAPID 폴백 모두 0회.
[실행 로그](turbo-run-1000-2026-09-23.txt).

측정은 `node src/run.js --mode turbo --pieces 1000`이며, 수치는 TURBO가 보고하는 `turboStats.effectivePps`다.
**`probe/validate_turbo.js`의 `acceptance()` 판정을 거친 기록은 아니다** — 합격 조건의 각 항목(500피스 이상,
의심 피스 제외 PPS ≥5, 의심 피스 ≤3%, 재동기화 ≤1%, 입력 오류·폴백 0)을 모두 충족하지만, 공식 합격으로
쓰려면 그 스크립트로 다시 받아야 한다.

실효 PPS는 구간 내내 4.93 → 5.03으로 단조 상승했고 한 번도 떨어지지 않았다. 검증 지연은 33~49ms로
400ms 제한의 1/10 수준이었다. 609피스에서 캡처 제한을 넘겨 폴백했던 이전 1,000피스 시도와 대비된다.

**보정은 환경마다 다시 떠야 한다.** 뷰포트 1295×999에서는 스폰 95ms가 42번째 피스에서 탈락해
**스폰 120ms + 회전·첫 이동 동시 입력**으로 저장됐다. 2026-09-21 합격 프로필(스폰 65ms)보다 보수적인데도
실효 PPS는 5.323 → 5.03으로 큰 차이가 없다. 보정이 안전한 쪽으로 수렴해도 예측 실행이 손실을 흡수한다.
창 크기가 바뀌면 보정이 무효가 되어 즉시 RAPID로 폴백하므로(`TURBO viewport changed`), 앱 재시작으로
창 크기가 달라진 뒤에는 보정을 다시 떠야 한다.

**함께 확인된 회귀 수정:** 같은 날 RAPID도 1,000피스를 리싱크 0·오배치 0으로 완주했다(400라인, 4.00 PPS).
직전까지 RAPID는 오배치 60%를 내고 있었고, 원인은 추적된 피스 정체성을 필드 위쪽 스폰 영역 판독으로
덮어쓴 것이었다 — 그 영역은 피스를 필드 경계에서 잘라내고 성운 배경이 비쳐, 실제 프레임에서 J를 L로,
축소 캡처에서 J를 I로 오인했다. 스폰 판독은 정체성이 없을 때의 부트스트랩 전용으로 제한했다.

**한계:** 이 구간에도 레벨 전환이 없었다(스테이지업 0). 전환 처리는 여전히 더 긴 런으로 확인해야 한다.

## 핵심 구현

- **예측·검증:** 최대 2피스 계획, 별도 캡처 연결, 검증 완료 전 후속 입력 차단. NEXT 공백은 건너뛰지 않는다.
- **입력:** 실측 보정에 통과한 기능만 사용한다. 타이머 지연 시 키 펄스를 압축하지 않는다. 프로필은 환경마다 다시 측정하며(뷰포트에 묶인다), 회전·첫 이동 동시 입력은 두 환경 모두에서 통과했고 스폰 지연은 65ms(2026-09-21) / 120ms(2026-09-23)로 달랐다.
- **화면·복구:** 화면 효과를 임시 고정하고 원래 설정을 복원한다. 레벨 전환 문구와 숨겨진 생성 영역을 읽으며, 재동기화는 전체 상태가 세 번 연속 일치해야 재개한다.
- **안전 제한:** 400ms 검증 제한, 지속 불일치·입력 오류 시 재동기화 또는 RAPID 폴백. 스폰 전 DAS 충전은 비활성화다.

코드는 [예측 루프](../src/turbo.js), [입력 모듈](../src/input/), [비전](../src/vision/vision.js)에 있다.
**Jev는 미도입:** 로컬 개선으로 목표를 달성했고 추가 효과를 입증하지 못했다. Jev의 현재 API·실성능을 별도로 검증한 것은 아니다.
