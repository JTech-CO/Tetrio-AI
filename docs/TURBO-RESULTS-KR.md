# TURBO 동작·검증

TURBO는 가장 빠른 속도입니다. 낯선 용어는 [README의 용어](../README-KR.md#용어)를 보세요.

## 동작 방식

BASIC과 RAPID는 피스를 하나 둘 때마다 화면을 읽고 나서 다음 수를 정합니다. TURBO는 다음과 같이 움직입니다.

1. NEXT에 보이는 피스로 **최대 2피스 앞까지** 둘 자리를 미리 정하고, 키를 쉬지 않고 보냅니다.
2. 키 입력 간격은 창 크기마다 미리 재 둔 값(**보정 프로필**)을 씁니다.
3. 화면 확인은 입력과 겹쳐 따로 진행합니다. 확인이 끝나기 전에는 다음 계획을 보내지 않습니다. 화면이 예측과 다르면 상태를 다시 맞추거나(재동기화) RAPID로 넘깁니다.
4. 레벨 전환이나 스택이 12줄 이상인 구간처럼 매 피스 확인이 필요한 때는 RAPID가 맡습니다. RAPID가 3피스 이상 두고 스택이 6줄 이하가 되면 TURBO로 돌아옵니다.

코드는 [예측 루프](../src/turbo.js), [입력 모듈](../src/input/), [비전](../src/vision/vision.js)에 있습니다.

## 실행과 보정

```bash
node src/run.js --mode turbo --pieces 500
```

- **자동 보정:** 보정 프로필은 창 크기마다 `probe/turbo-calibration-<w>x<h>@<dpr>.json`으로 따로 저장됩니다. 처음 보는 크기에서는 TURBO가 시작할 때 2~4분 동안 스스로 보정합니다. 이 동안 TETR.IO 창을 가리지 마세요. 창이 가려지면 게임이 멈춥니다.
- **창 모드로 실행:** 최대화 창은 화면 갱신이 느려 보정에 실패합니다(확인 지연 최대 269ms, 창 모드의 2~4배). 실패한 크기는 기록되어 이후 바로 RAPID로 진행합니다.
- **다시 보정할 때:** 키 설정·DAS/ARR·게임 버전이 바뀌면 `npm run turbo:calibrate`를 실행하거나, 보정 파일을 지워 자동 보정이 다시 돌게 합니다. 자동 보정은 프로필이 없는 크기에서만 돌기 때문입니다. 보정 파일은 머신별이라 Git에 넣지 않습니다.
- **공식 합격 판정:** `node probe/validate_turbo.js 500 --turbo-only --warmup`이며, 현재 창 크기로 보정된 상태에서 앱이 ZEN 화면에 있을 때 실행합니다. 결과는 `probe/turbo-validation-500.json`에 저장됩니다.
- **포트:** 프로브 스크립트의 포트는 `TETRIO_PORT`로 지정합니다(기본 9222).

같은 앱도 켜는 방식에 따라 창 크기가 다릅니다.

| 창 크기 | 이 크기가 되는 경우 | 보정 결과 |
|---|---|---|
| 1920×1010 | 꺼진 앱을 새로 실행(최대화) | 실패 → RAPID로 진행 |
| 1278×1002 | 최대화를 해제 | 스폰 대기 65ms + 회전·이동 동시 입력 |
| 1295×999 | 봇이 창 모드 앱을 재시작 | 스폰 대기 120ms + 동시 입력 |
| 1295×997 | 페이지에서 `window.resizeTo`로 조정 | 스폰 대기 65ms + 동시 입력 (자동 보정 약 2분 반) |

가장 보수적인 설정(스폰 대기 120ms)에서도 예측이 어긋난 크기만 "실패"로 기록하고 자동으로 다시 시도하지 않습니다. 계속 재시도하다 보면 운 좋게 한 번 통과한 불안정한 프로필이 저장될 수 있기 때문입니다. 캡처 지연이나 높은 스택처럼 크기와 무관한 이유로 멈춘 보정은 다음 실행 때 다시 시도합니다.

## 검증 결과

**공식 합격(2026-09-21): 500피스 / 93.940초 = 5.323 PPS.** 의심 피스·재동기화·입력 오류·RAPID 전환은 모두 0회였습니다([JSON](turbo-validation-500-final-2026-09-21.json)).

- 합격 조건은 다음을 모두 만족하는 것입니다.
  - 500피스 이상
  - 의심 피스를 뺀 PPS 5 이상
  - 의심 피스 3% 이하
  - 재동기화 1% 이하
  - 입력 오류·RAPID 전환 0회
- 연결, 첫 보정, 준비 주행 60피스는 측정에서 뺐습니다.

이후 장기 실행은 모두 `run.js`로 돌렸고, 공식 판정 스크립트는 거치지 않았습니다.

| 날짜 | 실행 | 결과 |
|---|---|---|
| 09-23 | TURBO·SINGLE 1,000피스 (1295×999) | 실효 5.03 PPS, 오배치 0 |
| 09-24 | TURBO·SINGLE 1,000피스 (1278×1002) | 실효 5.71 PPS, 오배치 0 |
| 09-24 | 자동 보정 + 200피스 (1295×997) | 실효 5.51 PPS, 오배치 0 |
| 09-25 | TURBO·QUAD 1,500피스, 레벨 전환 2회 포함 (1278×1002) | 실효 중앙값 6.98 PPS, 오배치 0 |

런별 상세와 개발 중 실패 기록은 [플레이 로그 모음](PLAY-LOGS-KR.md)에 있습니다.

## 한계

- 다른 PC나 게임 설정에서도 같은 속도가 나오거나 오배치가 없다고 보장하지 않습니다.
- 의심 피스는 불일치가 확인된 구간의 피스 수 전체입니다. 실제 오배치 수와 같지 않습니다.
- 외부 엔진(Jev)은 쓰지 않았습니다. 자체 개선만으로 목표를 넘었고, 추가 효과를 확인하지 못했습니다.
