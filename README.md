# TETR.IO ZEN 자동 플레이 봇

TETR.IO **데스크톱 앱**(Electron)의 ZEN 모드를 사람 수준 이상으로 자동 플레이하는 스크립트입니다.
CDP(Chrome DevTools Protocol)로 앱에 붙어 화면을 읽고(픽셀 비전), 검증된 테트리스 AI로 수를 계산해
키 입력을 주입합니다. 덤으로 앱 내 광고도 차단합니다.

> 이전 브라우저(`https://tetr.io/`) 시도가 실패한 근본 원인 두 가지 — **백그라운드 rAF 정지**와
> **포커스 이탈 시 일시정지** — 를 데스크톱 앱 + 아래 실행 플래그로 모두 해결했습니다.

## 빠른 시작

```bat
:: 프로젝트 폴더에서
start.bat
```

또는:

```bash
npm start                 # 무한 플레이 (실행 중인 앱 재사용)
npm run restart           # 앱을 새로 시작(스로틀링 해제 플래그 적용)
node src/run.js --mode rapid          # RAPID 모드로 바로 시작
node src/run.js --pieces 500          # 500개만 두고 종료
node src/run.js --restart --no-adblock
```

실행하면:
1. TETR.IO 앱이 켜져 있으면 재사용, 없으면 성능 플래그와 함께 새로 실행합니다.
2. 포커스 위조 + 광고 차단을 적용합니다.
3. **ZEN 화면**이 감지될 때까지 기다립니다 — 앱에서 직접 Solo → ZEN 으로 들어가 주세요.
   (ZEN 진행도는 계정에 저장되므로 앱을 재시작해도 같은 스테이지에서 이어집니다.)
4. 콘솔에 **모드 선택 메뉴**가 표시됩니다(8초 무입력 시 기본 모드로 자동 시작).
5. 플레이를 시작합니다. `Ctrl+C` 로 종료합니다.

## 플레이 모드

모드는 게임 화면 오버레이가 아니라 **봇 콘솔 창**에서 고릅니다. ZEN 감지 직후 메뉴가 한 번
나오고, **플레이 중에도** 콘솔에 `1`(basic)/`2`(rapid) + Enter 를 입력하면 즉시 전환됩니다.
`status` + Enter 는 현재 통계를 보여줍니다.

| 모드 | 속도(실측) | 오배치 | 방식 |
|------|-----------|--------|------|
| **BASIC** (기본) | ~2.4-2.6 피스/초 | ~0% | 매 턴 직렬 읽기 — 검증된 안정 프로필 |
| **RAPID** | 지속 ~3.4-3.7, 순간 ~4.2 피스/초 | ~3% (자가 교정) | 읽기·수읽기 파이프라인 + 정밀 키 타이밍 + 빔 탐색 |

RAPID가 빠른 이유 세 가지: (1) 하드드롭 직후의 화면 읽기와 다음 수 계산을 **스폰 대기 시간과
병렬로** 수행(임계 경로에서 ~70ms 제거), (2) Windows 타이머 양자화(15.6ms)를 우회하는 **정밀
키 타이밍**(탭당 ~42ms → ~26ms), (3) AI 2수 탐색을 상위 12개 배치로 **빔 프루닝**(품질 무손실
확인). 오배치는 매 턴 실제 화면을 다시 읽는 구조 덕에 다음 턴에 자가 교정됩니다.
한계선(실측): 60fps 입력 샘플링 때문에 탭당 ~26ms 미만은 키가 씹히고, 하드드롭 후 ~95ms의
스폰 여유가 필요합니다. 즉 이 입력 방식의 구조적 상한은 ~4.2-4.5 피스/초입니다.

## 동작 원리 (파이프라인)

| 단계 | 모듈 | 설명 |
|------|------|------|
| 앱 기동 | [`src/runtime/launch-app.js`](src/runtime/launch-app.js) | 디버그 포트(9222) + **스로틀링 해제 플래그**로 (재)실행 |
| 접속/입력 | [`src/runtime/cdp.js`](src/runtime/cdp.js) | CDP 연결, 키/마우스 주입, JPEG 클립 캡처 |
| 포커스 위조 | [`src/runtime/focus.js`](src/runtime/focus.js) | `visibilityState`/`hasFocus` 위조로 "OUT OF FOCUS" 방지 |
| 광고 차단 | [`src/runtime/adblock.js`](src/runtime/adblock.js) | 네트워크 도메인 차단 + 남은 컨테이너 CSS 숨김 |
| 비전 | [`src/vision/vision.js`](src/vision/vision.js), [`pieces.js`](src/vision/pieces.js) | 필드 자동 보정 → 10×20 보드 · NEXT 5개 · HOLD · 스테이지 변화 인식 |
| 두뇌 | [`src/board.js`](src/board.js), [`src/ai.js`](src/ai.js) | SRS 시뮬레이터 + Dellacherie 휴리스틱 2-ply 탐색 |
| 통합 루프 | [`src/bot.js`](src/bot.js), [`src/run.js`](src/run.js) | 화면 읽기 → 수 결정 → 키 실행, 매 수 재동기화 |

### 매 수(piece)마다
1. 플레이 영역만 JPEG로 캡처(≈70ms) → 디코드 → 10×20 보드 + NEXT + HOLD 읽기.
2. 낙하 중인 현재 조각을 최상단 컴포넌트로 분리(스택과 구분).
3. `pickMove()` 가 현재/HOLD 후보 × 모든 배치 × 다음 조각까지 2-ply 탐색으로 최적 수 선택.
4. `회전 → 좌우 이동 → 하드드롭` 키 시퀀스를 CDP로 주입.
5. 조각 정체성은 NEXT 큐 추적으로 유지하고, 화면의 4-cell 조각과 교차 검증해 어긋나면 재동기화.

## 핵심 기술 발견 (왜 이제 되는가)

1. **백그라운드 rAF 정지 → 해결.** 데스크톱 앱은 `backgroundThrottling: false` 라서 창이
   백그라운드여도 게임 루프가 계속 돕니다(측정: 백그라운드에서 ~107fps). 브라우저에서
   불가능했던 지속 플레이가 앱에서는 가능합니다.
2. **컴포지터 오클루전 스로틀링 → 해결(가장 큰 병목).** 창이 다른 창에 가려지면 Chromium이
   컴포지터를 스로틀링해 `captureScreenshot` 이 **프레임당 3~4초**까지 느려졌습니다. 앱을
   다음 플래그로 실행해 제거했습니다:
   ```
   --disable-backgrounding-occluded-windows
   --disable-renderer-backgrounding
   --disable-background-timer-throttling
   --disable-features=CalculateNativeWinOcclusion
   ```
   플레이 중에는 봇이 초당 ~2회 캡처하고 게임이 계속 렌더링하므로 컴포지터가 항상 깨어 있어,
   백그라운드에서도 캡처가 **~130ms(최대 ~500ms)** 로 유지됩니다. (초기엔 상시 스크린캐스트로
   컴포지터를 깨워뒀으나, 렌더러에 부담을 줘 ~5분 뒤 크래시·창 축소를 유발해 제거했습니다.)
3. **포커스 이탈 일시정지 → 해결.** visibility/focus API 위조로 "OUT OF FOCUS" 오버레이를 막습니다.
4. **광고가 필드를 가림 → 해결.** 앱 광고(Freestar/Primis 등)는 때때로 플레이 영역을 덮어 비전을
   망가뜨립니다. 네트워크 차단 + DOM 숨김으로 완전히 제거합니다.
5. **게임 상태는 픽셀로만.** 게임 내부 상태(`gamera`)는 광고 SDK일 뿐 보드 데이터가 없어,
   보드는 화면 픽셀에서 읽습니다. TETR.IO 기본 스킨은 I(청록)와 S(초록)의 색상이 겹치므로
   조각 종류는 **모양**으로 식별합니다(스택은 채움/빈칸만 필요).

## 성능 · 품질

- **AI 실력:** 빈 보드에서 1000개 배치 시 **399라인, 구멍 0, 최대 높이 2, 탑아웃 없음**
  (오프라인 시뮬레이션). Dellacherie 가중치 + 2-ply.
- **배치 정확도:** 라이브 검증에서 시뮬레이터 예측과 실제 화면이 8/8 일치, 실주행 150+피스
  동안 **리싱크 0회**(추적이 화면과 완벽히 일치). 회전·이동·하드드롭·HOLD·라인클리어 모두 확인.
- **속도:** BASIC **~2.4-2.6 피스/초**, RAPID **지속 ~3.4-3.7 / 순간 ~4.2 피스/초** — 평균 이상
  인간 플레이어 수준. 핵심 아이디어들: **낙하 대기 제거**(ZEN 중력이 "relaxed"라 새 피스가 화면에
  보이기까지 ~1초 걸리지만 스폰 즉시 조작 가능 → 큐 추적으로 정체를 알고 바로 배치), **읽기·수읽기
  파이프라인화**(RAPID: 캡처+AI 계산을 스폰 대기와 병렬 수행), **정밀 키 타이밍**(Windows 타이머
  양자화 우회). 매 턴 실제 보드를 다시 읽어 어긋난 배치는 다음 턴에 자가 교정됩니다(리싱크 0 유지).
- **창 크기 무관:** 필드 프레임을 자동 탐지(정사각 셀 제약)하므로 어떤 창 크기에서도 동작하고,
  60피스마다 재보정합니다.
- **자동 복구:** 렌더러 크래시·연결 끊김 등으로 실패해도 `run.js`가 종료하지 않고 재연결·재보정 후
   이어서 플레이합니다(반복 실패 시 앱을 자동 재시작).
- **장시간 무인 실행 (렌더러 열화 방지):** 앱을 아주 오래 켜두면 렌더러가 서서히 열화됩니다(광고
  SDK 누적 등으로 화면이 창 안에서 점점 축소되다가 멈춤 — BASIC ~7800, RAPID ~6000 피스 부근).
  이를 **선제적으로 예방**합니다: 기본값으로 **2500 피스 또는 20분마다** 앱을 깨끗이 재시작해
  렌더러를 새 것으로 되돌립니다(`--restart-every` / `--restart-mins`로 조정, 0이면 비활성화).
  ZEN은 계정에 저장되므로 재시작 후 봇이 스스로 **메뉴를 자동 조작해 ZEN에 재진입**합니다
  (자동으로 이어서 시작되면 그대로 감지, 아니면 Solo → ZEN → START를 자동 클릭 — 약 6초).
  진입에 실패하는 드문 경우엔 앱을 **다시 재시작해 재시도**하므로 사람이 없어도 무한히 돌아갑니다.
  또한 재시작 사이에도 화면이 비정상적으로 축소되면(열화 조기 감지) 즉시 재시작합니다.
- **탑아웃 시:** ZEN은 보드만 리셋되고 스테이지 카운터는 유지 → 봇이 자동으로 계속 진행.

## 요구 사항 · 설정

- Windows, Node.js 18+ (개발/검증: Node 25).
- TETR.IO 데스크톱 앱 설치: `%LOCALAPPDATA%\Programs\tetrio-desktop\TETR.IO.exe`.
- 의존성 설치: `npm install`.

### 명령행 옵션 (`src/run.js`)
| 옵션 | 기본값 | 설명 |
|------|--------|------|
| `--mode M` | basic | 시작 모드 (`basic` / `rapid`) — 실행 중 콘솔에서 언제든 전환 가능 |
| `--pieces N` | ∞ | N개 배치 후 종료 |
| `--port P` | 9222 | CDP 디버그 포트 |
| `--restart` | off | 실행 중인 앱을 끄고 플래그와 함께 새로 시작 |
| `--no-adblock` | off | 광고 차단 비활성화 |
| `--quality Q` | 85 | 캡처 JPEG 품질 |
| `--postdrop N` | 모드값 | 하드드롭 후 대기(ms) 강제 지정. 낮출수록 빠르지만 스폰 여유↓ = 오배치↑ |
| `--restart-every N` | 2500 | N 피스마다 앱을 재시작해 렌더러 열화 예방 (0=비활성화) |
| `--restart-mins M` | 20 | M 분마다 앱을 재시작 (0=비활성화). 피스·시간 중 먼저 도달하는 쪽 |

## 문제 해결

- **앱이 이미 켜져 있을 때 봇을 실행하면 앱이 재시작됩니다.** CDP로 부착하려면 앱이
  `--remote-debugging-port` 로 실행돼 있어야 하는데, 이 옵션은 실행 시점에만 줄 수 있습니다.
  그래서 디버그 포트 없이 켜진 앱은 봇이 한 번 껐다가 그 옵션과 함께 다시 켭니다(ZEN은 자동 재개).
  가급적 **`start.bat` 로 앱을 함께 띄우는 것**을 권장합니다.
- **"앱이 닫히고 다시 안 켜지는" 경우:** 이전 버전에서 봇/렌더러가 CDP 연결이 열린 채로 강제
  종료되면, 죽었지만 정리되지 않은 "좀비" 프로세스가 남아 단일 인스턴스 잠금을 붙잡아 앱이 안
  열릴 수 있었습니다. 지금은 (1) 종료 시 CDP를 항상 정상 종료하고, (2) 재시작 시 우선 CDP
  `Browser.close()` 로 깨끗이 닫고, (3) 좀비가 감지되면 봇이 매달리지 않고 명확한 안내로 실패하도록
  고쳤습니다. **이미 이 상태에 빠졌다면**: 작업 관리자에서 `TETR.IO.exe` 를 모두 종료하고, 그래도
  안 열리면 **PC를 재부팅**하면 잠금이 풀립니다(그 뒤론 재발하지 않습니다).
- 포트가 다른 프로세스와 충돌하면 `--port 9333` 처럼 바꿔서 실행할 수 있습니다.

## 주의

- ZEN 모드는 직접 진입해야 합니다(메뉴 자동 탐색 미구현). 봇은 ZEN 필드가 보이면 시작합니다.
- 창 크기를 바꿔도 필드를 자동 인식하며 60개마다 재보정합니다. 관전하기 편하게 TETR.IO 창을
   원하는 크기로 드래그해두면 됩니다(창이 너무 작으면 셀이 작아 인식이 약간 불안정할 수 있으니
   적당히 크게 두는 걸 권장).
- 화면이 흔들려 보이면 TETR.IO 설정 → 비디오에서 "화면 흔들림(shakiness)"을 꺼 보세요.
- 게임플레이 자동화는 TETR.IO 이용약관에 어긋날 수 있습니다. 개인 학습·연구 목적의 오프라인
  ZEN(무한반복) 한정으로 사용하세요. 온라인 대전에는 사용하지 마세요.
